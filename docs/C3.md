# VetClinic API — CLAUDE.md

Python 3.12 · FastAPI 0.115.6 · pydantic 2.10.4 · sqlite3 stdlib (sem ORM) · uvicorn. Código e mensagens em pt-BR. Contrato completo: `SPEC.md`.

## Imutáveis (NÃO ALTERAR)
`run.sh` `test.sh` `requirements.txt` `SPEC.md` `tests/acceptance/**`. Sem novas dependências. `main.py` deve expor `app`.

## Comandos
- Rodar: `./run.sh` (uvicorn main:app, 127.0.0.1:${PORT:-8000}, `DB_PATH` padrão `vetclinic.db`)
- Testes: `./test.sh` (todos) | `./test.sh tests/acceptance/test_aceite_agendamentos.py` (um arquivo) | `./test.sh -k nome` (filtro)
  - Sobe servidor com DB temporário em `TEST_PORT` (8765); log em `.server.log`. Testes são HTTP-only (`BASE_URL`), sem import do código.
- Não há lint/formatter/migrações. Schema via `CREATE TABLE IF NOT EXISTS`: mudar coluna exige apagar o `.db` local.

## Schema (db.py `SCHEMA`; todo `id` INTEGER PK AUTOINCREMENT)
- `tutores(nome NN, email NN, telefone)`
- `pets(nome NN, especie NN, tutor_id NN→tutores, data_nascimento TEXT 'YYYY-MM-DD')`
- `veterinarios(nome NN, crmv NN UNIQUE)`
- `produtos(nome NN, preco_centavos NN, estoque NN, estoque_minimo NN)`
- `agendamentos(pet_id NN→pets, veterinario_id NN→veterinarios, inicio NN, fim NN, duracao_minutos NN, status NN)` — datas TEXT `YYYY-MM-DDTHH:MM`
- `atendimentos(agendamento_id NN→agendamentos, anotacoes NN, produtos_json NN)` — JSON de `[{produto_id,quantidade}]` como enviado
- `faturas(tutor_id NN→tutores, atendimento_id NULL, status NN)` — `total_centavos` e `itens` NÃO são colunas
- `fatura_itens(fatura_id NN→faturas, descricao NN, quantidade NN, valor_unitario_centavos NN)` — `total_centavos` calculado em `faturas.montar`
- FKs declaradas mas `PRAGMA foreign_keys` NÃO ativado: integridade é verificada na aplicação.

## Regras de negócio → local
| Regra | Local |
|---|---|
| Email contém `@` (422) | `tutores.py` `TutorIn._email` |
| Tutor com pets → 409 no DELETE | `tutores.remover` |
| `data_nascimento` não futura (422) | `pets.py` `PetIn._nao_futura` |
| `tutor_id` inexistente → 404 (POST e PUT pet) | `pets.criar`, `pets.atualizar` |
| Espécie ∈ {cao,gato,outro} | `PetIn.especie` Literal |
| Pet com agendamentos → 409 no DELETE | `pets.remover` |
| crmv único → 409 | `veterinarios.criar` (captura `sqlite3.IntegrityError`; UNIQUE em SCHEMA) |
| Strings obrigatórias não vazias | tipo `Texto` (`comum.py`) |
| Monetários/estoque inteiros ≥0; quantidade >0 | `InteiroNaoNeg`/`InteiroPositivo` em `ProdutoIn`, `EntradaIn`, `ItemIn`, `ProdutoUsado` |
| Entrada de estoque soma | `produtos.entrada` |
| Ordem de validação do POST agendamento: 404 pet/vet → duração → futuro → expediente → conflito | `agendamentos.criar` (NÃO reordenar; formato de `inicio` é parseado após duração) |
| Duração múltiplo de 15, 15..120 (422) | `agendamentos.criar` |
| `inicio` > agora (422) | `agendamentos.criar` (`inicio <= datetime.now()` falha) |
| Expediente: seg–sex 08–18, sáb 08–12, dom fechado, mesmo dia | `agendamentos.EXPEDIENTE` (weekday 0–4, 5; ausente=6 fechado) + `dentro_do_expediente` |
| Conflito: vet, status ∈ {agendado,concluido}, intervalo semiaberto `inicio<novo_fim AND fim>novo_inicio` (409); cancelados liberam | `agendamentos.criar` (SQL) |
| `fim = inicio + duracao` | `agendamentos.criar` |
| Listagem agendamentos: filtros `veterinario_id`, `data` (`substr(inicio,1,10)`), ordem `inicio,id` | `agendamentos.listar` |
| Cancelar: só `agendado` (409); `momento` opcional; ≥24h → `cancelado`, <24h → `cancelado_tardio` | `agendamentos.cancelar` |
| Atendimento: ordem 404 agendamento → 404 produtos → 409 status → 409 estoque | `atendimentos.registrar` |
| Estoque somado por produto repetido na lista antes de comparar | `atendimentos.registrar` (`usado`) |
| Atomicidade: validações antes de qualquer escrita; tudo na mesma conexão/transação | `atendimentos.registrar` + `db()` |
| Efeitos: agendamento→`concluido`, estoque−=qtd, fatura `aberta` p/ tutor do pet | `atendimentos.registrar` |
| Valor consulta 15000 (primeiro item "Consulta" qtd 1); itens de produto na ordem enviada com preço atual (snapshot) | `atendimentos.VALOR_CONSULTA_CENTAVOS`, `registrar` |
| Total fatura/item calculado, nunca armazenado | `faturas.montar` |
| Fatura paga: não aceita itens nem novo pagamento (409) | `faturas._aberta` (usada por `novo_item`, `pagar`) |
| Faturas do tutor ordenadas por id | `tutores.faturas_do_tutor` |
| `estoque_minimo` só armazenado; sem regra associada | `produtos.py` |

## Convenções para código novo
- Um módulo por recurso: `router = APIRouter(prefix="/x", tags=["x"])` + registro em tupla de `main.py`.
- Modelos de entrada `XIn(BaseModel)`; tipos de `comum.py` (`Texto`, `Inteiro*`) em vez de `str`/`int` crus em campos obrigatórios; validação extra via `@field_validator` + `@classmethod` (→422 automático).
- Cada módulo define `buscar(c, id)` = `ou_404(um(...), "nome")`; outros módulos chamam `modulo.buscar(c, id)` para validar FK (→404).
- Handlers síncronos (`def`), `with db() as c:` por request; retornar dict/list direto (sem response_model). SQL cru com `?`, nunca f-string de valores. Criação: `inserir(...)` depois `buscar(c, id)`.
- Erros: `erro(status, msg)` (msg pt-BR minúscula); 404 via `ou_404`; DELETE → `Response(status_code=204)`.
- Listagens `ORDER BY id` (agendamentos: `inicio, id`).
- Datas/horas: strings; `FORMATO="%Y-%m-%dT%H:%M"` + `parse_data_hora`; hora local naive (`datetime.now()`).
- Dinheiro em centavos inteiros (`*_centavos`); derivados (totais) calculados na leitura.
- Validar tudo antes de escrever em operações multi-tabela; rollback automático por exceção em `db()`.
- Constantes de negócio em nível de módulo em MAIÚSCULAS.
- Estilo: type hints só onde úteis, docstrings curtas só em helpers não óbvios, imports `from x import ...` e módulos de recurso via `import modulo`.
- Mudança de contrato → atualizar `SPEC.md` é proibido: seguir o SPEC; ambiguidade → implementar conforme tabela acima.
